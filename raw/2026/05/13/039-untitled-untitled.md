# 龙虾退烧后，荣耀给它造了一个宇宙

每个技术浪潮都有一个相似的节奏：先是爆红、刷屏、被神化；然后热度退潮，留下少数还愿意继续打磨的人。 OpenClaw 也到了这个时刻。 热度退去后，真正重要的事才开始发生。 它需要的已经不只是更多掌声，还需要一个能让它长期生长的环境：更低的使用门槛、更稳定的体验、更可控的隐私，以及更合理的成本结构。 这恰好是硬件厂商最可能出手的地方。 也正是在这样一个时间点上， 荣耀，在 4 月 13 日的 PC 新品技术沟通会上，发布了一个看起来挺有意思的产品组合： 荣耀龙虾宇宙，YOYO Claw —— 一个把 OpenClaw 嵌进 PC、平板、手机里的「养虾本生态」。 紧接着的 4 月 16 日，首款搭载它的「养虾本」MagicBook 新品也正式开卖。 如果 OpenClaw 开创的“AI 自己动手”范式，能顺利进入荣耀生态，它带来的，很可能会是一次用户习惯层面的变化。 「十字路口」团队实测了几天，将体验和观察分享给大家。 YOYO Claw 小龙虾宇宙到底是什么？ YOYO Claw 小龙虾宇宙的核心结构，基本可以一句话讲清楚： 在荣耀的 PC、平板、手机三端，每一端都内置一只小龙虾，每一端都可以养虾。 要看清楚这套产品的整体逻辑，从 PC 端切入是比较直接的方式。我们专门联系，新购入了一台荣耀 MagicBook Pro 作为实测设备。 登录荣耀 PC 端的 YOYO Claw 之后，第一感受是界面层的简化。 原来 OpenClaw 在终端里的命令行式对话，在这里被收成了一个更接近聊天工具的界面。 在这一层，你可以直接给小龙虾配置人设、性格等参数。 系统里已经内置了一批针对不同场景的小龙虾，覆盖电脑用机、自媒体运营、文档处理等方向。 按官方口径，现在的荣耀 YOYO Claw 出厂预置了 5 个成品主虾、23 个子虾，覆盖教育、办公、学术、内容创作和智能辅助 5 个场景。 从用户视角看，不需要配 API、不需要设置模型路由、也不需要写 Skill，基本是一个开箱即用的状态。 除了几只内置的小龙虾之外，在它的 Bot 市场里也可以找到更多小龙虾，配置流程做了简化，点击添加即可。 在主小龙虾里，常用能力都已经预置好。图片理解、图片生成这些通用模块，以及对应的技能(Skill)，基本都已配置完成，不需要用户再单独装一遍。 因为整套系统直接内置在荣耀 PC 里，小龙虾对本机的操作权限做得比较深。比如下载安装 Steam、QQ 这类常见软件，它可以自己打开网站、调用工具、走命令行执行安装，中间不需要用户介入。 对开发者向的工具也一样适用。让它在本地安装 Claude Code 并配置好依赖环境，流程也是它自己跑完。 也可以让它直接去 GitHub 上搜索具体项目，比如 CCC Switch 这种小工具，它会先抓取项目页面、再执行安装。 本机存储管理也能交给它处理。比如让它扫一遍 C 盘，列出占用空间较大的文件，再由用户决定要清理哪些。 在偏研究类的任务里，小龙虾可以连续完成数十轮的网页搜索和工具调用。 实测中，我们让它做了一个相对深度的研究任务，主题是梳理 AI Agent 在面试场景下的海内外明星初创产品。整个研究最终生成了一份万字以上的报告。 由于它本身具备 Agent 属性，这份研究内容会被自动整理成一份排版过、格式相对完整的 Word 文档，直接存到本地。 代码编程类任务也能跑。比如让它生成一份多卡片风格、整体排版过的 HTML 展示页，完成度还可以： 把上面这些场景串起来看，荣耀 PC 端的 YOYO Claw 在产品取向上有一个比较明显的偏好: 把使用门槛压到最低。 由于系统出厂内置，所有 Skill 和能力模块都已提前配好，这套设定让它在家庭、教育这类相对轻量的场景里跑得比较顺。一个具体的例子是教育场景下的判题:对相对简单的选择题图片，它能给出还可以的识别精度。 实测中，我们告诉它桌面上存在几张需要判题的截图，它会先在本地把图片找出来，做分类，然后连续进行 14 轮工具调用，逐张执行图片识别任务。 一轮识别完成之后，它会自查一遍内容，如果发现信息有缺失，会再走一轮识别。所有内容最终会先写成一份 Markdown 文档，后续可以再让它整理成一份 doc 文档，整体处理速度还可以。 DOC 文档里的批改报告会做基础的格式化处理。需要说明的一点是，因为底层是 AI 在做图片识别，所以选择题这类结构化题目识别效果较好，大题的解读会更吃力一点。 在 YOYO Claw 里，荣耀 PC 端原生支持手机远控。系统已经把几条接入路径内置好，关联流程基本是点击两下就能完成连接。 比如扫描微信场景的二维码之后，可以快速在手机端创建一个微信 ClawBot。 另一个值得说的设计是，荣耀 PC 端的 YOYO Claw 支持接入本地大模型。这是荣耀 PC 在介绍中反复强调的一个点。 公开信息层面，有一个值得记录的数字： 相比直接使用社区版 OpenClaw，YOYO Claw 在 PC 端的综合 Token 消耗下降约 50%，这一数据来自荣耀官方披露。背后的机制是「端云协同、端侧优先」的路由。 逻辑大致是这样:简单任务在端侧处理，复杂任务再走云端。 平板 在 YOYO Claw 宇宙里，PC 其实是最后一个补上的端侧。最早出现的是平板，其次是手机，PC 反而是这套体系里最后落地的一环。 平板端内 ，荣耀通过 Linux 桌面环境为底层提供运行支持，并预装了一键部署脚本。用户在荣耀平板上，基本可以通过几次点击完成 OpenClaw 部署。 在荣耀平板上打开 YOYO Claw，部署流程基本被简化为几次点击。不需要像 PC 社区版那样手动配环境、安依赖，系统已经帮用户把 OpenClaw 的运行环境打包好了。 荣耀为此设计的具体使用路径是，通过 Pad 端开发者模式，进入到 Linux 实验室内设的桌面，进行安装。 这件事的直接意义是： 过去开发者群里争论了很久的「平板能不能跑 Agent」，在这里有了一个相对完整的答案。 平板上跑起来的虾，能力集和 PC 端同源，但受限于平板本身的算力和使用场景，它更偏向轻量任务：本地文件整理、笔记归类、简单的图文生成。和 PC 端的关系，更像是「同一只虾在不同设备上的不同形态」。 手机端 YOYOClawPhone 手机端是荣耀这次布局里一个相对不同的东西。它和 PC、平板上的虾有本质区别。 PC 和平板上的虾，更多依赖远程连接， YOYOClawPhone 先锋版则可以直接在安卓机上跑。 这意味着，它更像一只真正的端侧虾。 手机不再只是发指令的入口，也可以自己调用 App、文件和设备能力，去完成一些具体操作。 它的上手门槛也更低： 安卓手机一键安装，界面对新手更友好；Skill、记忆和数据都保留在本地，不上传云端。除了信息整理、内容处理这类常规任务，它还可以直接操作手机和 App，用“零触控”的方式处理一些生活里的小事。 它更像是在给不同设备之间搭桥。无论是安卓手机、PC、平板，还是其他智能硬件，只要能接入这套体系，就可以被不同的“虾”调动起来。 任务也不再只靠单个 Agent 来做，可以拆给多个角色一起完成。这样一来，硬件不再只是等待指令的设备，它们被分配了角色，开始参与到一套可协作的 AI 网络里。 它把 AI Agent 分成了几种更容易理解的角色：可以帮你干活的、可以陪你聊天的，也可以更偏情感陪伴的。 这套设计有点像是在给“虾”做人设。它不只负责执行任务，也试图让用户在使用过程中产生一点熟悉感和陪伴感。说得更直白一点，就是把一只工具虾，慢慢养成一只更懂你的虾。 简单说，YOYOClawPhone 想做的，不是再给手机加一个 AI 助手入口，而是把“虾”直接放进手机里。 它可以在安卓机上本地运行，调用手机里的应用、文件和设备能力，也能和其他硬件发生联动。这样一来，手机就不只是发指令的遥控器，也开始变成一台可以自己执行任务的 AI 设备。 这件事的意义在于，OpenClaw 不再只围着 PC 转。它开始进入移动端，也让“人手一只虾”这件事，变得更接近普通用户的日常。 YOYO 控虾 在这三端之上，YOYO 控虾是这套系统里一个相对独立的能力，核心逻辑是 手机作为入口，远程连接并指挥 PC 上的虾执行任务。 接入流程在 PC 实测部分已经提过，系统内置了几条关联路径，基本点击两下就能完成连接。扫描微信场景的二维码后，可以在手机端快速创建一个微信 ClawBot，作为手机和 PC 之间的通信通道。 连接完成之后，手机端的 YOYO 和 PC 端的虾之间，会形成一条双向通道。 比如下面这几个典型的跨端场景 【1】 手机发指令，PC 执行。 【2】 PC 上的虾，调用手机端的能力（短信、通讯录）。 【3】 定时任务与主动推送。 把这几个场景串起来看，YOYO 控虾的定位是比较清晰的： 手机在这套结构里，承担的是入口和遥控器的双重角色。 你不需要走到每台设备面前操作，只要在最常握着的这块屏幕上发指令，分布在 PC、平板甚至三方云上的虾，就会各自执行并回传结果。 按官方介绍，YOYO 控虾的兼容范围不限于荣耀自家设备，也支持接入部署在三方云、三方设备上的 OpenClaw。也就是说，只要协议对得上，一台手机可以统一调度多个不同来源的虾。 说白了，YOYO 控虾想做的事，是让 AI 不再停留在“你问一句，它答一句”的阶段。你在手机上说一句话，它就能去调动 PC、平板，甚至其他地方的虾，把一串任务接着做完。 它瞄准的，是过去 AI 最容易让人劝退的几个问题：任务做不连贯、配置流程太折腾、长期用下来成本高，以及权限放出去之后总让人有点不安心。 聊到这里，有一个问题绕不开： 小龙虾越能干，它能碰到的东西就越多。能整理桌面文件的同时，也意味着它有权限读到你在桌面的私人信息。 这就是为什么 OpenClaw 这类东西，做得越好，大家越有担忧的原因。YOYO Claw 在这一层，做了比较多的 Action。 比如， 核心数据只在本地处理 。所有个人记忆、敏感数据都留在设备里，不上云。甚至有一个叫做 设备级独立安全虾 的虾，会监控其他虾的 AI 操作，比如格式化硬盘、重装系统这种，虾就不会做。 其他的，像是支付、打开摄像头之类的敏感操作会进行二次确认 。 OpenClaw 爆火之后，真正的问题才刚刚开始 爆火的 OpenClaw 让人激动的点之一就是：它可能是第一次让普通人也能知道如何让 AI「自己动手干活」。 但实际部署、使用过一段时间的人，大概都会同意一句话： 新鲜感过去之后，OpenClaw 还停留在「好玩具」的阶段，离「助手」还差一段距离。 可能至少有三件事，会让你慢慢丧失耐心。 【1】装完之后，需要养虾。 OpenClaw 本身是开源的，理论上人人都能跑。但实际操作起来，环境配置就会劝退一大批人。这种门槛，在程序员圈里能扩散，但很难真正扩散到普通用户，所以这也是为什么许多厂商下场的基础。 其次，装完之后，还需要养。在这一步上，普通用户并没有太多关于「养」的思维。 【2】Token 太贵。 OpenClaw 的工作方式，是让模型不断「记忆、思考、行动、再思考」。一段稍微复杂一点的任务，半小时跑下来，可能十几、几十块钱就没了。 我们身边有朋友说，自己装好的第一周，每天都在看仪表盘。而 OpenClaw 的这一特性，甚至让 Claude 等厂商直接封禁利用会员订阅额度去使用 OpenClaw。 【3】隐私问题。 把电脑的桌面控制权交给一个跑在云端的产品，多少会有些担忧。 这三件事加起来，会导致一个很常见的局面: OpenClaw 在朋友圈里被传得非常热，但你打开身边十个用过它的人的电脑，大概率有八个，已经一个月没再点开过。 回头看，这其实是任何一个新技术走向大众的必经之路。 OpenClaw 现在缺的并不是更强的能力，它缺的是一个「家」。 我们其实可以拿 Linux 来类比一下。Linux 内核 1991 年就出来了，但它真正走进千家万户，靠的并不是内核本身，而真正起作用的，是 Ubuntu 这种把它打包成「开箱即用」的发行版。 没有 Ubuntu，Linux 可能永远只是黑客的玩具；有了 Ubuntu，它才有机会变成一个普通人也能用的操作系统。 OpenClaw 现在差的，基本上就是这样一个「Ubuntu」。 那么问题就来了: 谁来做 OpenClaw 的 Ubuntu? 从直觉上讲， 这件事最适合做的玩家，其实就是手机和 PC 厂商。因为它们手里同时有三样东西:硬件、操作系统、用户。 而荣耀这家手机厂商，就是在这个背景里出现，并给出了上面我们实测后的尝试性答案： YOYO Claw 宇宙。 拉远一点看:手机厂商和 AI 能力，正在进行一次重要的碰撞 那么，YOYO Claw 在手机厂商内，走的是什么路线？ 过去半年，「AI 自己动手干活」的能力，从 OpenClaw 这种偏开发者的开源框架，开始往大众消费品迁移。一个比较显眼的节点，是 2025 年 12 月，字节跳动联合中兴推出豆包 AI 手机工程样机，首批 3 万台被一抢而空，二手市场最高溢价超过 3500 元。 这台手机最受关注的能力，是系统级 GUI Agent，也就是 AI 直接读取屏幕、模拟点击，跨应用完成连贯任务。 它把一件事推到了行业台面: 当一个超级 Agent 能越过应用沙盒，直接看屏幕、直接点屏幕，能力的天花板和隐私的底线，就正面撞上了。 争论之后，行业里慢慢露出了两条路线。 【1】 系统级 GUI Agent 。 【2】 端侧 + A2A(Agent to Agent) 两条路线之外，行业里还有一个慢慢形成的共识： GUI Agent 想真正做大，绕不过「端侧化」。 端侧 AI Agent 能力不是一个性能概念，它是 GUI Agent 大众化的前提。 谷歌通过 Private Compute Core 把更多个人数据计算任务放回设备本地;OPPO 在 ColorOS 里推「记忆共生引擎」，数据不上云;苹果在系统层面也有类似动作。 把 YOYO Claw 放回这个图里，荣耀这次的位置就比较清楚了。 它没有选激进的系统级 GUI Agent 路线，也没有走纯协议级的 A2A。它的切入点，落在了端侧 AI 这一支：把 OpenClaw 这套开源框架，在终端侧重新组织了一遍。 往长一点看，YOYO Claw 这件事呼应的，是 荣耀在更高一层的两个表述：阿尔法战略「三步走」(智慧手机、智慧生态、智慧世界)，以及 AHI(智启人本，Augmented Human Intelligence)。 这两个概念听起来略抽象、略宏大，但落到 YOYO Claw 这个具体的产品组合上，目标其实可以归到一句相对朴素的愿望: 让 AI Agent 这件事，变得安全、便捷、经济，可以被普通人长期用下去。 放在端侧 Agent 路线之争的背景里，这种选择，得上是手机厂商对端侧 AI 的一次比较完整的尝试。 YOYO Claw 现在还有它自己要解决的问题，成熟度还需要时间打磨，三端互联是不是还要有更顺畅、更没有摩擦感的交互。 这条端侧 Agent 路线，依然需要靠真实场景、真实用户来验证，现在还没有现成答案。 但回头看 AI 这几年，从大模型，到
