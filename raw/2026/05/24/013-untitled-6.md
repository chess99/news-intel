Iris：帮你看清网站在悄悄做什么 @少数派39937550 ： 几个月前，我在逛一个海外科技论坛时看到一个帖子，有人用 Chrome 开发者工具的 Network 面板打开了某个新闻网站，结果发现页面加载时发出了 47 个请求，其中只有 3 个是真正和新闻内容有关的。其余 44 个都是广告系统、用户追踪、数据分析服务。我意识到普通人根本没有办法看到这些非必要但和隐私密切相关的请求——你需要会用开发者工具，需要知道哪些域名属于哪些公司，需要懂得区分第一方请求和第三方请求。这些门槛加在一起，把 99% 的用户挡在外面了。 于是我开始想，能不能做一个工具，把这些东西直接摆到普通人面前。于是便有了 Iris 这款浏览器扩展。 Iris 选择了 Disconnect.me 的开源数据库，这是 Firefox 浏览器内置的追踪保护名单，覆盖 6000 多个域名，并且一直在更新。Iris 每 7 天会自动从 GitHub 拉取一次最新版本缓存在本地，既保证数据库实效性，又避免了每次请求都要联网下载数据。 追踪器的「浏览器指纹」这边，即使我们没有登录任何账户、清空了 Cookies 缓存，网站也可以通过读取显卡型号（Canvas/WebGL 渲染结果）、音频硬件特征、屏幕分辨率、已安装字体等信息，拼出一个在统计上几乎唯一的、你的设备画像。考虑到这些读取操作发生在页面 JavaScript 里，不是网络请求，用 webRequest API 也根本监听不到，Iris 采用了一种「注入主世界」的办法，在页面 JavaScript 执行之前，把监听代码插入到页面的执行环境里，包装原生的 canvas.getContext() 、 AudioContext 、 navigator.geolocation 等 API，一旦有人调用就记录下来。 当然了，类似的功能其实也有很成熟的工具在做了。Iris 真正特别的，是 AI 服务监测和假冒 AI 网站识别。这两个功能来自我的一个观察：过去两年 AI 产品井喷，用户对 AI 这个标签已经高度信任。这种信任也变成了钓鱼网站的攻击面。很多网站哪怕看起来只是一个普通的客服对话框，背后也在调用外部的 AI 接口，而用户并不知道自己说的话会被发往哪里、被哪个模型处理、数据由谁来保管。 Iris 会检测页面发出的网络请求目标域名，如果命中已知 AI 服务商的接口域名就会显示出来。目前已经覆盖了国内外主流的二十多个 AI 服务商，包括常见的几个大厂接口和开放 API 平台。这个功能当然不是用来制造恐惧的——很多情况下网站调用 AI 是完全正常的。但我想通过 Iris 让你知道这些数据的去向。 至于假冒 AI 网站识别，这块是最让我有点担心的功能，因为容易误报。Iris 目前采用的做法是维护一个「正版域名白名单」，任何其他域名如果在 URL 里包含对应关键词、但同时又不在白名单里，就会触发警告。所以误报是真实存在的，比如一些正规的 AI 教程网站、API 封装服务，域名里也包含这类词。我目前的处理方式是保守一点——只对域名本身做匹配，不做页面内容分析，错误率可以接受。但确实还需要更多真实场景的打磨。 最后，很多人第一次看到 Iris 的时候可能也会好奇 Iris 为什么只做信息展示、不直接做拦截。这是一个有意为之的选择。 拦截有很多成熟的工具在做，uBlock Origin 就很好。但拦截本质上是一个「黑盒」操作——你知道结果，不知道原因。我更想做的是让你「看得见」，看见之后，你自己来决定接不接受。有的追踪你觉得无所谓，有的你觉得不能接受，这本来就是个人判断，不应该由工具代替你做。 这种设计哲学借鉴了「可观测性（Observability）」这个概念——服务器领域有 Datadog、Grafana 这类工具，不是用来「修复」问题，而是把系统内部状态暴露出来。Iris 想做的是浏览器里的观测性工具。 目前 Iris 还有几个没做好的地方，比如某些正规网站会被错误标记为「可疑」，尤其是假冒 AI 网站那个功能。如果你遇到误报，欢迎在 GitHub 附上网址和截图提个 Issue；扩展目前内存占用大约 4MB，比 uBlock Origin 轻一些，但在某些有大量第三方请求的页面，弹窗打开可能会有轻微延迟，目前我还在优化。 如果你想试试，Iris 扩展完全开源，你可以在 GitHub 或 Chrome 应用商店 下载安装。 扩展阅读： 我做了一个 Chrome 插件，帮你看清网站在悄悄做什么 和隐私獾结合使用？ 6 2 Ophel Atlas：给和 AI 聊天聊「迷路」的人 @urzeye ： 我有一个坏习惯：喜欢在同一个 ChatGPT 对话里聊很久。讨论需求、推翻方案、再来一版、再推翻……有时候聊到一半我会突然意识到，前面某一轮我们好像达成过一个共识，但我不记得在哪里了。 于是我开始滚屏，向上滚，滚过三十条、五十条、一百条消息，眼睛扫描每一段文字，试图找到那个关键的结论。有时候能找到，有时候找到之后发现记错了，有时候什么也没找到，只是把自己搞得更乱。 我想这个问题应该不只是我有，解决方法其实也不复杂。我需要的不过是一个目录。就像读一本书时目录页的作用：你知道整本书的结构，你可以跳转，你不会迷路。于是我写了 Ophel Atlas。 Ophel Atlas 一开始只做一件事：在 AI 对话旁边，实时生成一份可点击的大纲。AI 每回复一条内容，大纲就自动更新一次。点击任意条目，页面直接跳转到对应位置。不需要搜索、不需要滚动、不需要记忆。 从「无限滚动的聊天记录」到「可导航的 AI 文档」 但光有大纲还不够，当我把这个工具分享出去之后，有用户提到另一个问题： 我的对话太多了，根本找不到之前聊过的那个。 这是另一种「找不到」——不是在对话里找不到，而是在对话之间找不到。于是 Ophel Atlas 有了会话文件夹。你可以把不同主题的对话归类整理，就像给文件建文件夹一样直观。文件夹支持标签、置顶、批量操作、搜索定位。 会话文件夹 还有一些用户说，他们有一套固定的提示词，每次都要重新打一遍，或者从别处复制粘贴，很麻烦。 于是 Ophel Atlas 又有了 Prompt 词库。你可以把常用的提示词存进来，需要时一键填入输入框，双击直接发送。支持变量替换、分类、置顶。 提示词词库 这些功能都不是我一开始设计的。它们来自用户真实遇到的问题，然后一个一个被加进来。平台这边，我最初只适配了 ChatGPT 和 Gemini，后来是 Claude、Grok，然后是 DeepSeek——因为有越来越多的人开始用它了。现在 Ophel Atlas 支持了 15 个 AI 平台。 值得一提的是，Ophel Atlas 的数据全部存储在本地。设置、Prompt 词库、会话管理数据，都在你自己的浏览器里，不经过任何服务器。无需注册账号，无需登录，按需申请权限。如果你使用多台设备，可以选择接入自己的 WebDAV 服务同步数据，整个过程完全在你的掌控之中。在 AI 工具普遍需要账号、采集数据的今天，这是我觉得值得坚持的一件事。 Ophel Atlas 也是免费的，没有 Pro 版、没有付费墙，你可以通过 Chrome 应用商店 、 Firefox Add-ons 、 Greasy Fork 或 GitHub 下载安装。如果你也是每天和 AI 打交道的人，如果你也曾经在长对话里迷过路，可以去试一试。Chrome 用户可以在 Web Store 搜索「Ophel Atlas」，Firefox 用户可以在 Firefox Add-ons 找到它。如果觉得有用还请在商店里留一条评价，对一个独立开发者来说，这比什么都重要。 的功能很简单，设置好专注、休息时长，填入想要生效的 URL，然后照常使用浏览器，并静待猫咪在设定的时间后出现即可。 这款扩展上线时，默认出现提醒你放松一下的是一只憨态可掬的橘猫，走进你的浏览器窗口后，它会席地而坐、露出丰腴的腰腹然后闭目养神——是在提醒屏幕前的各位也要这么休息一下了！要是休息够了或者你看得不耐烦了（怎么会呢），点击扩展面板里的「Shoo, kitty!」即可赶走它。 为了避免大家感到腻味，开发者在后续的更新中除了上面提到的自定义 URL，也加入了另一只三花猫作为客串嘉宾随机出现： 总体来说 Cat Gatekeeper 确实不是那种严肃的网页浏览时长限制、管理工具， 首先它猫咪的数量还不够多， 猫咪遮罩强制全屏在某些情况下可能会失效。工作狂是拦不住的。 所以它更像是给爱猫人士的浏览器小玩具，把自律说教包装成一只闯入你浏览器窗口的猫咪，甚至连最轻量的互动都没有——你只需要看着可爱的猫咪打盹，然后给自己也简单放几分钟假，去接口水喝或者走两步吧。 你可以在 Chrome 应用商店 下载安装 Cat Gatekeeper。 1 day1tabs：给标签页太多的你 @克莱德 ： 我并不是那种会留着两位数标签也不管、然后留着它们过夜的人（或许是因为穷买不起大内存的电脑吧），所以也没有过早上起来看着前一天留下的、密密麻麻的标签页不知所措的经历。所以 day1tabs 的入围单纯是觉得它的理念很有意思。 如果你之前尝试过大名鼎鼎的 Hermes Agent，应该知道 Hermes 相比 OpenClaw 有一个自动会话重置的机制在——在设定的时间（推荐设置是凌晨）自动重置会话，避免上下文过长和因为忘记重置带来的会话上下文污染。 day1tabs 也是同样的理念：每天到点儿自动清理标签页，第二天打开浏览器总是全新的。day1tabs 会在后台学习我们当天的标签页使用情况（所有数据本地保存）。很少打开的、重复打开的标签页，到了设置的时间点就会被自动关掉，固定标签页和常用的标签页则会保留下来。 除了可以相对灵活（可以提前手动清理，但要是能设置多个时间点比如早中晚，应该会更符合打工人的使用习惯）地自定义自动清理时间， day1tabs 还会在清理概要页面提供标签页使用情况概要和重新打开标签页的选项。个人使用下来唯一的问题是 day1tabs 不能保存浏览器分组状态，被关掉的分组标签页在恢复打开后也无法重新分组。如果你比较依赖标签页分组功能，建议去给开发者 提个 issue 。 你可以在 Translate 除了声明具有更好的隐私外，其翻译结果是通过 AI 模型（具体是何种模型并未披露）输出的。因此，除了翻译结果整体更流畅之外，它的语言支持也更广，例如可以将广东话改写为书面中文，或者自娱自乐地翻译到东北话。 如果你更习惯「沉浸式翻译」风格的中英对照翻译，好消息是 Kagi Translate 同样支持类似显示方式，在展开后的工具栏选择 Bilingual 即可。遗憾的是目前做得还不完善，例如并不能把双语显示作为默认样式，而且对于页面元素的处理比较机械，会出现将无需翻译的非正文内容（例如广告）复制一份的情况——只能说沉浸式翻译受欢迎是有原因的。 除了翻译之外，Kagi Translate 插件还整合了校对和词典功能，同样是由 AI 模型输出的，也非常实用。特别是校对功能，除了常见的风格控制功能外，还会详细解释每项改动建议的原因。 Kagi Translate 还提供了一系列国外社交及媒体平台的整合功能，打开后就会在 YouTube 字幕、X 帖文等位置看到 Kagi 的翻译按钮，从而获得比官方机翻更好的效果。 Kagi Translate 支持 Chrome 和 Firefox 浏览器，大多数功能是免费的，只有少部分（例如更长思考时间的 Best 模式翻译）需要 Kagi 订阅，并不影响使用。不过如果有兴趣的朋友也可以借此试试 Kagi，相信不会失望。 4 Imp Translate：沉浸式翻译轻量替代 @克莱德 ： 如果你不喜欢沉浸式翻译、一时间找不到功能上能够完全替代它的同类工具，但日常浏览网页的过程中又实在离不开翻译工具，Imp Translate 是一个不错的轻量替代方案。 Imp Translate 内置微软、谷歌两种免费翻译服务，同时提供 OpenAI 兼容 API 的自定义 API
